# PWLA — Proton Wine Log Analyzer

Generic offline **game.log reader and error amplifier** for any game running under Proton/Wine or natively. Reads game log files, highlights critical error patterns by severity, filters results, and exports reports — helping you diagnose crashes and mod issues without repeatedly launching the game.

## About

**PWLA (Proton Wine Log Analyzer)** is a Python-based offline tool for anyone debugging game crashes, mod issues, or engine errors. It reads `game.log` (or any text log) files generated by games running under Proton/Wine or natively, and highlights critical error patterns by severity:

- **Critical**: access violations, segmentation faults, fatal errors, panics, aborts
- **Error**: missing files, unexpected tokens, crashes, assertion failures, failed loads
- **Warning**: deprecations, cautions
- **Info**: loading, initialization, startup messages

It was originally built for *Call to Arms - Gates of Hell* modding but works with **any game** that produces text log files.

## Features

- **Parse** any text log file (`.log`, `.txt`, or any extension)
- **Highlight** error lines by severity: critical, error, warning, info
- **Filter** to show only errors/warnings with a checkbox toggle
- **Export** filtered error reports to text files
- **Open** the log in your system's default text editor with one click
- **Customize** the error patterns via `error_patterns.json` — add your own keywords per severity
- **No external dependencies** — runs on Python 3.8+ with tkinter only

## Installation

```bash
git clone https://github.com/Mauricio5494/PWLA_Proton-Wine-Log-Analyzer.git
cd PWLA_Proton-Wine-Log-Analyzer
```

No external Python dependencies are required — it runs on Python 3.8+ with the standard library only (**tkinter** is included with Python 3.8+ on most installations).

### System Dependencies

| Platform | Requirement |
|----------|-------------|
| **Windows** | Python 3.8+ installed from [python.org](https://python.org). During installation, check the box **"tcl/tk and IDLE"**. |
| **Linux** | Python 3.8+ and the `python3-tk` package (on Debian/Ubuntu: `sudo apt install python3-tk`). |
| **macOS** | **Not supported** (by author's decision). |

## Running without a terminal (double-click)

You do **not** need to open a terminal to use the GUI.

### Windows

Double-click **`run_gui.bat`**. It launches the app with `pythonw.exe` (no console window).

### Linux

1. Make the launcher executable:

   ```bash
   chmod +x run_gui.sh
   ```

2. Double-click **`run_gui.sh`** in your file manager, or run:

   ```bash
   ./run_gui.sh
   ```

3. Optionally, copy **`PWLA.desktop`** to `~/.local/share/applications/` to add it to your desktop environment's application menu.

## Usage

1. Launch the GUI: `python3 gui/main.py` (or double-click `run_gui.bat` / `run_gui.sh`)
2. Click **Browse…** and select your log file (`game.log`, `console.log`, or any text log)
3. The log loads automatically with color-coded severity:
   - **Red (critical)**: access violations, segfaults, fatal errors
   - **Orange (error)**: missing files, crashes, assertion failures
   - **Yellow (warn)**: deprecations, cautions
   - **Green (info)**: loading, initialization messages
4. Toggle **Show errors only** to filter out informational lines
5. Click **Export report…** to save the filtered errors to a text file
6. Click **Open log file** to open the raw file in your system's default editor
7. Click **Edit error patterns…** to customize the keywords per severity level

## Custom Error Patterns

PWLA reads `error_patterns.json` in the repo root. You can add, remove, or modify keywords per severity level. The file is watched at startup and can also be edited from the GUI via the **Edit error patterns…** button.

Example structure:

```json
{
  "critical": [
    "EXCEPTION_ACCESS_VIOLATION",
    "segmentation fault",
    "panic"
  ],
  "error": [
    "error",
    "file not found",
    "ctd",
    "crash"
  ],
  "warn": [
    "warning",
    "deprecated"
  ],
  "info": [
    "info",
    "loading"
  ]
}
```

Each severity maps to a list of keywords. A line is tagged with the first severity whose keywords match (case-insensitive).
